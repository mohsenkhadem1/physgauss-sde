# Runner/auditor shared draft contract

All file/output record paths and dependency keys are canonical repository-relative strings, resolved only by `resolve_repo_path`. CLI `--output` and `--prelaunch-seal` follow the same rule. No real seal or physical resolved stage has been generated by this task.

`validate_seal(seal_path, cell_id)` returns `(protocol, manifest, cell, pins)` and permits already-existing outputs for auditing. `validate_prelaunch` additionally requires the exact fresh declared output and OMP_NUM_THREADS/OPENBLAS_NUM_THREADS/MKL_NUM_THREADS each `2`. A separate driver must respect the reviewed bounded concurrency declaration; the runner does not schedule workers.

The seal requires schema `actual-authored-force-prelaunch-seal-v0.1`, status `REVIEWED_PUBLISHED_EXECUTION_SEAL`, and true `physical_launch_authorized`/`sources_and_stage_manifest_published`. This is an internal source/provenance contract, not an additional user confirmation flow. Fields `protocol`, `resolved_manifest`, `authored_auditor_source`, `small_force_complete60_audit`, `resource_declaration` are `{path,sha256}` records. `source_sha256` is exactly `dependencies()`. Auditor path is exactly `experiments/campaign_authored_force_audit.py`; its hash must also match manifest `authored_auditor_source_sha256`. Resource JSON has integer `threads_per_worker:2`, integer `max_parallel_workers:1..8`, `gpu_used:false`.

Resolved manifest: schema `actual-authored-force-resolved-stage-v0.1`, status `FROZEN_PUBLISHED_RESOLVED_EXECUTION_MANIFEST`, `stage`, `protocol_sha256`, `source_sha256`, `authored_auditor_source_sha256`, `cells`. Each row copies template fields `case,scenario_id,response,output_hz,relative_tolerance,absolute_tolerance_N,translation_m,maximum_iterations,kind` exactly and adds `template_id,id,hz,output`. Initial stage requires all 51 unique exact temporal rows and IDs. Matched IDs are `<template_id>__hz<resolved_hz>` and require `temporal_candidate_proof:{path,sha256}`. Conditional temporal refinement is deliberately rejected here until separately reviewed.

Candidate proof: `protocol_sha256`, `auditor_source_sha256`, `accepted_candidates:{scenario_id:entry}`. Driven entry fields: `passed,physics_hz,output_hz:20,frames:61,geometry_residual_checks_passed,source_evidence_records:[{path,sha256,role}],all_actual_rates_hz,force_induced_signal_m,tolerance_m,full_driven_temporal_metrics,full_zero_temporal_metrics,all_adjacent_errors_m:{driven:[...],zero:[...]}`. Each full metrics object includes `adjacent_coordinate_rmse_m` and `passed`. Guard verifies complete allowed history, exact family-specific tolerance and separate adjacent-error contraction; independently reviewed auditor computes those values from actual trajectories. Shared moving-zero entries are in `accepted_zero_candidates['t0003__zero_external_force'][str(hz)]`, with `passed,physics_hz,output_hz,frames,geometry_residual_checks_passed,source_evidence_records,passing_family_ids`; every linked driven family must independently pass at the same rate.

Output `private-provenance/` contains numbered source/proof copies; `pins.json` maps original relative path to SHA; `snapshots.json` maps original_path/saved_path/sha256; `static-reference.npz` contains exact untranslated source arrays; `physical-inputs.json` records case/spec/hardware/lineage. `protocol.json` contains exact cell, model limitations, dependency pins and compiled force metadata. `compiled-commands.npz` stores all compiler arrays. `engineering-public/` and `known-parameter-diagnostic/` have separate `features.npz`/`manifest.json` groups and explicit non-admission labels.

`steps.jsonl` contains accepted endpoint rows only: unchanged core ledger except redundant all-zero nodal array removed, with exact request/actual clocks, geometry, stable handle increments, start/end origins, per-handle work and moments. `trajectory.npz` contains `times_s,actual_state_times_s,positions_m,velocities_point_chord_m_s,auxiliary_positions_m,auxiliary_velocities_point_chord_m_s,handle_centers_m,handle_rotations,force_interval_actual_times_s,force_midpoints_compiled_s,force_step_commands_N,handle_work_each_J,moment_about_world_origin_start_end_Nm`. `summary.json` hashes trajectory/steps and reports actual-clock signed/absolute impulse, first moment, work and geometry ranges; it claims no qualification. `execution.json` must have both terminal/completed true for success.

Failures preserve `failure.json`, `last-accepted-state.npz`, `failure-endpoint-state.npz`, `partial-trajectory.npz` where available, `failure-endpoint-ledger.json` when a row returned, and detached `unaccepted-core-locals.npz` when available. Only bounded named locals/history are copied; no traceback/model/autograd graph is retained or serialized. Failure is re-raised; outputs remain immutable and no replacement is attempted.
