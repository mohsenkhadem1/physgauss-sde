BOWL STUDY: FROZEN RUN AND REPRODUCTION GUIDE
===========================================

Run commands from the repository root. Raw arrays and checkpoints remain local.
This guide describes the 7 November 2026 campaign, not a newly authorized run.
Its simulation deadline is 2026-11-07 21:44:00 UTC. See the final section before
attempting a later reproduction: the original deadline must not be bypassed by
silently editing the frozen experiment.

Scientific scope
----------------
The soft object is a tapered, curved, nonbox tetrahedral solid with mass
0.12809501019059244 kg. It falls under gravity into a known open hemispherical
bowl of radius 0.09 m. The material is compressible Neo-Hookean; contact uses
actual material-surface triangle quadrature, a penalty and regularized friction.
The bowl has no rim thickness. There is no CCD or self-contact model.

Unknowns are Young's modulus and one friction coefficient shared by bowl and
pusher. Geometry, density, Poisson ratio, viscosity, gravity and the rigid-body
position/rotation commands are known. The pusher enters through the open rim;
it does not enter through the wall. Calibration pushes are POSITION-controlled,
not known-force inputs. Bowl rotation has a fixed spherical center and unchanged
gravity: its informative effect is tangential wall velocity and friction.

Sixteen parameter worlds = 4 moduli x 4 friction coefficients. Four supplied
surface correspondences yield overhead metric x/y coordinates with independent
0.5 mm coordinate noise. This is not an end-to-end RGB reconstruction study.
Initial observations: 0.08 and 0.12 s. Exactly one reset calibration experiment:
25 mm x-push or 0.2 rad bowl rotation. New observations: 0.94 and 1.2 s. A
separate held-out reset experiment uses a 45 mm transverse y-push. Future motion
is scored at 1.1, 1.2 and 1.3 s over 64 common material nodes, including internal
simulation-only ground-truth nodes. The primary event is MAP point RMS >3 mm.

The action menu has a fixed budget of one experiment. It is not a proceed/cost
optimization. Both fixed actions, initial/no correction, and the same-evidence
MAP predictor are retained. Utility uses 128 fixed common Gaussian noise draws
per hypothesis, without consulting selected-world held-out target measurements.

Primary inference: 16 hypotheses, n=6 mesh, nominal dt=25 microseconds.
Matched control: this same finite forward dictionary is true by construction.
Finer space/time stress: n=12 and dt=12.5 microseconds, same rest geometry.
Two independent noise replicates per world per cohort give 64 records; they are
NOT 64 independent objects. There are 16 parameter worlds across both cohorts.
Uncertainty summaries bootstrap these 16 world clusters, preserving replicates.

A SECONDARY 32-hypothesis comparator admits both resolutions with prior 0.5 each
and the same uniform 16-parameter prior within each. The finer reference belongs
to this mixture BY CONSTRUCTION. This is a controlled numerical-model-uncertainty
comparison, not robustness to arbitrary unknown physics. It also receives the
exact observation selected by the coarse policy (shared_coarse_active), so model
uncertainty can be compared under identical corrective evidence.

Reaction forces are withheld outputs, never inference sensors. Secondary force
metrics use the trailing 20 ms boxcar average accumulated at every integration
step, at the three held-out times. Bowl and tool are separate: vector RMS in N,
MAP and posterior mean, and marginal 90% coordinate coverage/width. Force sign
is force exerted by the soft object on the rigid body. The 20 ms window is not
described as a 50 Hz sensor bandwidth. Unfiltered reactions are retained too.

Production worker commands (original run, before its deadline)
------------------------------------------------------------
Only ONE worker should own each role/checkpoint path. Check worker-*.json and
the OS process list before starting or resuming. All commands below run from
the repository root with the stated environment:

  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 CUDA_VISIBLE_DEVICES=1 \
    .venv/bin/python -u -m scripts.gap_first_v01.bowl_worker inference-and-target

  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 CUDA_VISIBLE_DEVICES=0 \
    .venv/bin/python -u -m scripts.gap_first_v01.bowl_worker reference-push

  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 CUDA_VISIBLE_DEVICES=2 \
    .venv/bin/python -u -m scripts.gap_first_v01.bowl_worker reference-rotation

GPU1 generates all three n=6 interactions and then the n=12 held-out push.
GPU0 generates the n=12 calibration push; GPU2 generates n=12 rotation.
CUDA_VISIBLE_DEVICES maps that physical GPU to the code's logical cuda:0.

The actual durable launch used Python subprocess.Popen with start_new_session=True,
stdin=DEVNULL, stdout/stderr redirected to worker-ROLE.log, and the above
environment. Example for one role (repeat only for roles not already running):

  import os, subprocess
  env = os.environ.copy()
  env.update(OPENBLAS_NUM_THREADS='1', OMP_NUM_THREADS='1', CUDA_VISIBLE_DEVICES='1')
  log = open('reports/gap-first-v01/bowl/worker-inference-and-target.log', 'a')
  process = subprocess.Popen(
      ['.venv/bin/python', '-u', '-m', 'scripts.gap_first_v01.bowl_worker',
       'inference-and-target'], env=env, stdin=subprocess.DEVNULL,
      stdout=log, stderr=subprocess.STDOUT, start_new_session=True)
  print(process.pid)

GPU integration writes periodic progress JSON and atomic restart checkpoints
under runs/gap-first-v01/bowl/checkpoints/. These contain current x/v, accumulated
statistics, saved frames, partial force impulse and next integration step.
Restart validates engine source, configuration, theta, timestep and interaction.
checkpoint-audit.json verifies exact interrupted/resumed CPU-position and force
agreement. GPU/NumPy parity and force/torque/momentum tests are also retained.
The deadline guard checkpoints and stops; do not relaunch past the deadline.

Reproducible invariant/parity/restart checks (these are development tests, not
production-bank generation):

  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
    .venv/bin/python -m scripts.gap_first_v01.bowl_tests
  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
    .venv/bin/python -m scripts.gap_first_v01.bowl_runtime_checks --device cpu

To check an authorized idle GPU, set CUDA_VISIBLE_DEVICES to that single GPU and
use --device cuda:0 with a new --output diagnostic filename. Do not compete with
an active production worker merely to repeat an already-passed parity check.

Do not kill other training/simulation jobs. Worker status records contain the
specific owned PID. The original PIDs are historical; consult current records.
If an interruption leaves a corrupt trajectory NPZ, preserve it with an explicit
interrupted suffix, document the event, and regenerate from the matching source/
checkpoint before creating bank/prediction seals. Never silently reuse corrupt
arrays or overwrite an already-scored scientific run.

Finalizer and manual stages
---------------------------
The CPU-only durable finalizer waits for all GPU roles and requires all 96
complete trajectory NPZ files. It then aggregates banks, seals and scores
predictions, audits every declared camera observation and saved surface,
and renders fixed-world 0 figures/videos plus the all-world plot and
new TeX section:

  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 CUDA_VISIBLE_DEVICES='' \
    .venv/bin/python -u -m scripts.gap_first_v01.bowl_finalize

Use the same detached Popen pattern with finalization.log for crash resistance.
Do not run multiple finalizers. Its canonical status is finalization.json.
Before starting it manually, ensure its recorded PID is not already running.

Equivalent manual scientific stages, ONLY after all parallel workers finish:

  .venv/bin/python -m scripts.gap_first_v01.bowl_campaign generate --n 6
  .venv/bin/python -m scripts.gap_first_v01.bowl_campaign generate --n 12
  .venv/bin/python -m scripts.gap_first_v01.bowl_campaign seal
  .venv/bin/python -m scripts.gap_first_v01.bowl_campaign predict
  .venv/bin/python -m scripts.gap_first_v01.bowl_campaign score
  .venv/bin/python -m scripts.gap_first_v01.bowl_report

generate validates cached trajectories and attempts any missing CPU cases;
this must not race an active GPU writer. This manual missing-case retry is NOT
performed automatically by the finalizer. The finalizer instead writes
requires-review and stops with a missing/invalid/failure list. If any required
hypothesis fails,
the failure is retained and accuracy evaluation does not proceed by excluding it.
The finalizer then calls bowl_audit for all 96 physical trajectories and
bowl_publication for the artifact set. All declared overhead observations are
checked against deformed surface triangles, the pusher and the rotated bowl.
Any occluded points remain in the report and cases: they invalidate a fully
camera-visible interpretation rather than being silently filtered out.

Retained development failures and numerical limits
-------------------------------------------------
Development records preserve the original larger drop, coarse quadrature,
rejected side-entry pusher path, and the n=12 dt25 us failure. The production
tool enters from above with positive wall clearance. The n=12 dt12.5 us soft/
stiff controls completed, minimum J 0.271/0.372. The n=6 half-step target difference
was 0.35 mm. The n=6-to-n=12 space/time target differences were 1.42/2.81 mm, close
to the 3 mm decision tolerance. These are numerical approximation/stress results,
NOT a converged-continuum or real-physics certificate. See numerical-qualification.
json, imported-dependency-seal.json and the development JSON files.

The PhysTwin spring-core adapter failed the imposed positive-tetrahedron-volume
check at impact across CPU/GPU and timestep checks. native-qualification.json
retains exact attempted scales, steps and author-kernel provenance. It is excluded
from accuracy rankings; this is not a conclusion about full native PhysTwin.
