Direct baseline feature pack — prepared, no dataset generation or training

API: feature_pack.build_features(scene,prescribed_pose,node_material,query_material,bulk_law,interface_law,probes=...,checkpoint_sha256=...). The caller supplies the explicit2x6 position/rotation-vector command; no action-label lookup or response-derived pose is used. Material coordinates lie in[0,1]^3. Reference query positions are returned for rendering via the same GeometrySpec.map used by mechanics.

Default dimensions: nodefeatures[N,81], globalfeatures[88], queryfeatures[Q,9]. N andQ are arbitrary; collation buckets equal counts per batch. No scene name, arbitrary geometry ID, held response, observed force or deformation target enters features. Heterogeneity pattern0/1 is the same explicit spatial-function descriptor used by the oracle solver, not a scene identity.

Node: material coordinate3, reference position3(m), local bulk descriptor3, left/right endpoint indicators2, seven bulk coupon fingerprints of10 values each. Query: material coordinate3, reference position3(m), local bulk descriptor3. Global: geometry dimensions/taper/arch5, prescribed two-tool poses12(m,rad), gravity3(m/s²), density1(kg/m³), bulk descriptor3, heterogeneity amplitude1/pattern1, two interface descriptors6, centers4 and widths4(unit-face coordinates), two interface coupon fingerprints24 each.

Public bulk probes, fixed before scene dataset access:
I; diag(1.10,.95,1); diag(1.30,.90,.90);1.05I; and simple shearsF=I+gamma e_x⊗e_y at gamma=.1,.3,.6. Each fingerprint is energy density(Pa) plus row-major first Piola stress(Pa). It evaluates the frozen scale-separated learned law at that node's actual oracle descriptor.

Public interface probes delta(m): (0,0,0),(.001,0,0),(.003,0,0),(.006,0,0),(0,.003,0),(0,0,.003). Each fingerprint is energy(J) and traction xyz(N), using the same normalized-area shared attachment law as mechanics. These are bilateral-law coupons, not contact data or ground-truth scene reaction labels.

Checkpoint paths and digests are explicit loader arguments. The interface checkpoint may be replaced after a separately declared development update; its reference length/basis count/width are loaded from checkpoint metadata. Hashes are provenance, NEVER network features. Actual numeric coupon outputs enter the tensors. Probe lists are likewise explicit and included in the feature contract; changing probes or checkpoint versions prevents mixed-contract collation. No normalization is fitted here.

Fairness: both approaches receive the same oracle physical descriptors and access to the frozen shared laws. The direct network receives a finite coupon summary of those laws; mechanics evaluates the full energy during equilibrium. This is a declared information representation difference, not additional scene supervision. The shared laws' constitutive coupon training is separate from the direct model's scene-response supervision. Neither comparison implies inferred-latent generalization; an inference experiment must replace oracle descriptors consistently for both approaches.

Saved label API: load_labelled_record(scene,metadata,label_path,...), metadata={scene_id,split,prescribed_pose}. NPZ keys exactly material_query[Q,3], displacement[Q,3], wrenches[2,6]. Labels must have a supplied SHA256, finite arrays and matching query count. Only declared train/validation scenes are admitted; this training loader rejects reserved/test roles before opening the label file. Scene IDs stay metadata for split enforcement, not network input. batch_records feeds the existing train-only normalization/training helper. Multiple actions may share a scene ID within its single declared split.
