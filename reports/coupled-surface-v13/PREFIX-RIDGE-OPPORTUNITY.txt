Decision: feasible as a small, separately declared exploratory ablation; not implemented or launched. No new physical parameter optimization or simulation needed. It is not already included in the existing family selector. Improvement is a hypothesis, not guaranteed; no future target was read for this design.

Minimal prospective experiment
Keep all148 archived cases and old predictions/results byte-identical. Label every cohort post-inspection exploratory, including originally fresh/confirmation cohorts. Freeze input manifests, source hashes, fixed regularization0.1 and existing70% observation cut before reading new suffix scores. Do not select only PhysTwin cases because its aggregate motivated this idea.
1. Export a strict predictor payload: known initial geometry, observed prefix/mask, controller tracks and times. Recompute SoftVT grasp/attachment parameters on the SHORT prefix (trim_prefix already does this); no inherited full-prefix grasp or feature normalization for SHORT fitting.
2. Fit a standalone ridge implementation from that payload at SHORT cut. Use the same fixed features/penalty as archived baseline. Fit once again on full permitted prefix only after selection. Use direct observed-point ridge predictions for validation and initial-only interpolation for final geometry; carefully document/test whether this exactly reproduces original position_ridge or introduces a nodal interpolation difference.
3. Reconstruct SHORT prediction of the existing selected physical configuration from its cached independently SHORT-fit anchor and the SHORT payload; reuse stored rigid configuration when selected. No physics rerun. Recompute its validation error from actual observed-prefix points instead of trusting rounded scalar metadata.
4. Primary minimal ablation: fixed default is exact archived selected output. Switch to ridge only when finite withheld-prefix RMS is strictly<.98*default RMS; ties/allfail preserve exact old output. Freeze any topology/feasibility handling symmetrically before fitting. Do not rescue failed full forecasts using future errors.
5. Optional separate fixed blend ablation: weights{0,.25,.5,.75,1}, prediction=(1-w)*physical+w*ridge, scored on the same observed-prefix window, deterministic default-first tie handling. This requires both validation arrays reconstructed on precisely the same point set; stored scalar errors alone cannot score blends. Do not silently add data-dependent weights, extra regularization searches or dataset-specific rules. If time is short, use the simple switch only.
6. Persist chosen rule, all candidate prefix scores and forecast arrays before a separate scoring process opens suffix targets. Report every case, all failure counts, unchanged defaults, per-dataset means/paired differences and physical validity diagnostics. Do not pool SoftVT coordinate RMS and PhysTwin manual-track means. Keep known privileged SoftVT initial-geometry caveat.

Compute estimate and boundedness
Ridge solves matrices with roughly25features for two controller groups (one group roughly13), not FEM time steps. CPU-only fit/interpolation should be small; precise runtime has not been benchmarked here. Recorded prior cached-adapter reproducibility replay took roughly4.8–32.5seconds per case in a fixed12case sample, including all configurations, so recomputing one selected SHORT adapter across148 is plausibly tens of CPU minutes, not new multi-hour physics fits. Data decompression, scene/contact replay and topology checks could dominate. Budget1–2CPU workers with the original absolute deadline, no GPU needed. Reject this opportunity for this campaign if required input export/replay cannot be audited and bounded without displacing final report/publication.

Leakage/interface risks to resolve first
- Existing general loaders eagerly load evaluator future object arrays. SoftVT HDF permits prefix-only slicing, so a dedicated exporter can avoid suffix reads. PhysTwin final_data.pkl is a monolithic pickle: unpickling materializes future object arrays; use a quarantine exporter that exposes only initial/prefix arrays and known controls, with explicit provenance/audit, or an already sanitized prefix cache. No sanitized standalone observed-prefix NPZ was found in inspected v12 caches. Do not pretend current cache is sufficient by itself.
- Full-prefix ridge predictions cannot serve as SHORT validation predictions. Normalization, coefficients, grasp and support mappings must respect the SHORT cut.
- Existing physical family/configuration selection already uses this withheld observed-prefix window; adding another chooser increases validation reuse. This is permitted only as openly exploratory model selection, not a new unbiased generalization result. More elaborate nested validation would add work and is not required for the minimal fixed ablation, but claims must acknowledge reuse.
- Ridge uses initial sparse/full support geometry. A direct nodal output rewrite changes RBF interpolation relative to archived position_ridge. Verify an exact safe baseline reproduction on synthetic inputs before attributing improvement to family selection.
- Convex trajectory blends are not necessarily valid deformations or feasible contacts. They are empirical predictions, not an upgraded coupled physical solver; report any inverted elements or scene penetrations and do not claim physical consistency.
- Selection metric is observed-prefix coordinate RMS, whereas PhysTwin primary final metric is manual-track mean; no measured manual suffix tracks may guide selection or weight choice.
