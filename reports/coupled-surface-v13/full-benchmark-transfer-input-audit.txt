FULL COUPLED BENCHMARK TRANSFER: INPUT FEASIBILITY (read-only development audit)
2026-10-30. No future object targets, new predictor runs, selected results, or frozen source changes.

Decision: no honest immediately runnable full coupled transfer on both public datasets from the verified inputs. SoftVTBench offers a concrete author-asset acquisition path for the exact tactile robot, but the declared soft-object/evaluation asset bundle is currently unavailable at its documented official endpoints. PhysTwin supplies controller points, not an observed closed hand collision surface. Neither justifies inventing finger collision geometry or treating evaluator-only FEM states as ordinary visual inputs.

SoftVTBench input contract
Author README lines 60-67 explicitly restrict policy inputs to visual/tactile/proprioceptive streams and language. FEM states are evaluator-only, never supplied to the policy. HDF initial nodal_pos_w and subsequent FEM trajectories are therefore privileged simulator state. Our prior deformation benchmarks using initial nodes are a separately defined privileged-geometry prediction task, not the official visuo-tactile task-completion benchmark. Any new adapter must state extra known robot geometry/initial FEM geometry and match those inputs across methods. Initial-state rigid poses also require explicit disclosure rather than assuming they are policy observations. Future commanded/recorded robot motion is an action-conditioned forecasting input, not future object observation.

Local schema inspection (one existing development demo; only initial node coordinates read)
182 initial pastry nodes; no tet indices in its deformable-object group. Robot joint_position/root_pose, arm_joint_pos, two gripper positions and eef_pose exist as dataset fields. Full robot joint kinematics can be recovered without force measurements; exact q-to-collider transforms must be validated against the corresponding runtime robot variant. Old adapter only used eef pose/width and heuristic attachments; it does not establish that mapping. Initial nodes are already in an equilibrated/deformed state, not automatically stress-free authored geometry. Material parameters in USD cannot be handed to an unknown-material predictor as labels. Density must be explicitly known or inferred, not silently replaced with 1000.

PhysTwin
Source depth conversion divides millimetres by1000, so reconstruction has a metric convention. Local initial point/surface/interior representations and controller tracks do not supply closed hand collider geometry or a physical density. Author trainer builds radius-graph controller springs and unit particle masses; it is not evidence for known hand collision meshes. Some upstream preprocessing refers to reconstructed final_mesh.glb, but that mesh was not present in the inspected local case directory. Do not unpickle full final_data/gt tracks merely to look for input geometry: they include future object targets. Legitimate narrower transfer remains prescribed controller attachments plus declared ground, not general scene-level rigid-hand contact.

Implementation prerequisites beyond assets
Our consistent P1 mass/FEM can accept arbitrary tetrahedra, but production surface/sparse quadrature assumes box rest geometry. Arbitrary pastry/plush boundary quadrature, closed-mesh collision queries and exact robot-link transforms need a separate tested adapter. Delaunay tetrahedralization from observed nodes could be a disclosed approximation; it is not author topology and must handle concavity and invalid tets. Existing v12 normalized stiffness/gravity ratios cannot directly become SI stiffness in v13. Initial geometry estimation and prefix-only fitting must be separated from held-out trajectories.

Concrete next development-only path
Obtain the missing author evaluation pastry/scene asset bundle or an author-confirmed replacement URL; retrieve and compose the exact tactile robot dependencies above; resolve the actual data-collection env variant and validate joint/frame transforms using initial robot state only; extract units, initial collider geometry and a valid soft volume mesh; choose either a privileged-geometry system-identification contract or reconstruct geometry from permitted observations. Then implement arbitrary surface quadrature/mesh contact and fit only an observed prefix with input-matched baselines. Until those prerequisites are met, keep the current qualified controlled simulation study and archived public-data results separate. No performance gain or official benchmark comparison is claimed by this audit.
