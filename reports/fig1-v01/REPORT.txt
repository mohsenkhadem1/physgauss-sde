1. QUESTION AND SET-UP
After the same initial footage (D0) and the same single calibration interaction (D1), which method best predicts a
new interaction?  Every method receives the same rendered RGB frames (11 cameras; camera 0 held out) and the same
known commands.
  S1  stem, new push D2c: 20 N at 0.75 L along (0,-0.8,-0.6) (unseen direction). Score: RMS 3-D displacement of
      4 material stations over all 37 frames (mm).
  S2  block with a hidden 8x stiffer region (left / centre / right), off-centre press D2 at x=-0.07. Score: RMS 3-D
      displacement of 27 top-surface probes over 25 frames (mm).
  S3  stem, rigid striker impact D3 (0.3 kg sphere, 1 m/s) and free rebound. Primary score: striker impulse
      error (N s); also station RMS (mm).
  Worlds: stem W500/W1000/W2000 (rho 500/1000/2000, equal E/rho); block Bleft/Bcentre/Bright.
  S1 and S3 share the stem objects and every method's stem fits.

4. CAVEATS THAT AFFECT INTERPRETATION (read before quoting the numbers)

4.1 The test is well specified for ours.  The references come from the same FEM family ours uses as its forward
    model (protocol "known_limits": ours uses a coarser mesh and linear elasticity; the stem reference is
    nonlinear). On the stem the true (E/rho, nu) = (4000, 0.3) lies exactly on ours' parameter grid
    (C_GRID = geomspace(1000, 16000, 49)); after calibration the posterior collapses onto that grid point in every
    world, which is why ours' three sensor variants agree to 1e-9 m. On the block the inclusion position (+-0.06, 0)
    and nu (0.4) are grid values; only the soft modulus (6e4, deliberately between grid points) and the contrast
    (true 8, MAP 4) are off-grid. The other methods each use their own simulator; the oracle row (GIC's simulator
    with the TRUE parameters: 8.1 mm on S1, 7.9 mm on S3) shows that simulator mismatch alone costs them several mm.
    Much of the gap therefore measures simulator match plus a well-placed hypothesis space, not inference alone.
    Recommended next test (not part of these sealed results): off-grid true parameters and a reference solver that
    differs from ours' (other mesh/element order, nonlinear material), and the real-data PokeFlex experiment.

4.2 Ours' block calibration is uninformative.  The posterior over 1443 hypotheses is already a point mass after
    the initial press, so D1 changes nothing (before = after, identical to machine precision).

4.3 Input provenance: PAC-NeRF rewrites shared scene images (found 2026-11-14, after scoring).
    Our renderer writes each frame as data/r_C_F.png and an identical data/m_C_F.png. PAC-NeRF's native
    preprocessing (vendor/pac-nerf/train.py:73) overwrites m_*.png IN PLACE with background-matted versions
    (pixels with matting alpha < 0.9 set to white) every time it fits a scene. r_*.png are never modified.
    Who read what:
      - ours (and M-PhyGs and PhysTwin, which were given ours' RGB-triangulated marker tracks; their photometric
        losses are off, see 5) read m_*.png through rgb_track.py. The sealed tracks were made 2026-11-09 14:06-14:07:
        stem D0 from frames PAC-NeRF had matted at 14:03; stem D1 from raw frames (PAC-NeRF matted D1-W500 at
        18:13 that day and D1-W1000 / D1-W2000 on 2026-11-12). Block tracks were made before any block PAC-NeRF fit.
      - GIC's reader also reads m_*.png (vendor/gic/scene/dataset_readers.py:474). By file timestamps every GIC
        fit used here ran on unmatted frames: stem fits 2026-11-08 21:16 to 2026-11-09 08:29 (first stem matting
        14:03), block fits 2026-11-09 14:37 to 22:52 (first block matting 23:17).
      - PAC-NeRF reads r_*.png and writes its own m_*.png (its native pipeline).
    No method received extra information (matting only whitens pixels), but ours is sensitive to it. Post-hoc,
    UNSEALED sensitivity run (scratch; re-tracked every episode from the current, matted frames, same code):
      D1 marker-track p95 error rises from 0.7-1.1 mm to 2.6-10.0 mm (LK loses markers near whitened edges);
      S1 after calibration: ours 1.27 -> 3.10 mm mean [2.70 5.79 0.80];
      S3 after calibration: station RMS 0.51 -> 1.86 mm [1.19 3.66 0.73], impulse error 0.003 -> 0.034 N s
      [0.010 0.087 0.006]; S2 unchanged (block tracks change by < 0.01 mm).
    Ours remains best on the mean in S1 and S3 under this perturbation but not in every world (S1 W1000: 5.79 vs
    M-PhyGs 0.79). The tracker has no outlier rejection; this is a genuine robustness limit of ours' front end.
    Fix for future runs: render to a read-only copy per method, or point every reader at r_*.png.

4.4 The FEM control failed.  The 6x2-bin log-E + nu Levenberg-Marquardt fit ran its bins to the bounds (1 kPa to
    3 MPa against a true 60-480 kPa) and predicts 25-94 mm displacement against ~4 mm. It is a broken control, not
    evidence for ours. It is reported as sealed; any refit would be post-hoc and must be labelled so.

4.5 PAC-NeRF on S3 is a geometry failure.  Its reconstructed stem is ~0.19 m thick (true 0.08 m), so the striker
    starts inside the body: at t=0 the striker velocity is (1.0, -0.2, 0.8) m/s instead of (0, 0, -1) and it leaves
    the scene. The contact adapter is the same one GIC, M-PhyGs and PhysTwin use.

4.6 PhysTwin on S3: off-axis contact on the spring-mass lattice gives a lateral striker rebound (-0.34 m/s in x).

4.7 GIC simulator with true parameters (oracle) is worse than fitted GIC on S1: the GIC MPM with the true E, nu
    does not reproduce the FEM reference; fitted parameters partly compensate.


5. METHOD ADAPTERS AND DEVIATIONS FROM NATIVE (full lists in each method's README)
GIC (official b523851) and PAC-NeRF (official b613048): raw RGB, cameras 1-10; native fit on D0, native refit on D1
  (initialised from D0); labelled force adapter (gic_force_adapter.py) and striker contact adapter
  (striker_adapter.py, contact law b = 1e11 (r - |x-c|) n N/m^3 for every method). PAC-NeRF fixes during the run:
  the stem D0 fit record (fit.json) was rebuilt from its checkpoint after a crash in the writer (values E 1.494e6,
  nu -0.165 read from the checkpoint; no time recorded); forecast reads the scene path from fit.json; adapter
  force buffers are re-allocated on first use (PAC-NeRF creates particles after the simulator). PAC-NeRF nu is
  bounded to [-0.45, 0.45] natively.
M-PhyGs (scripts/fig1_v01/mphygs, README lists 16 deviations): no image/DINO stage (gsplat and transformers could
  not be imported); photometric terms are dummies with weight 0, so M-PhyGs is fitted to the same RGB-triangulated
  marker tracks as ours; fixed density 1000 and nu 0.3; curriculum 12/24 frames (stem D1 12/24/36), 150 Adam
  iterations per stage; material initialised at E0 = PAC-NeRF's initial modulus (3e4 block, 4e5 stem) because the
  native initialisation froze; position loss rescaled to a 1 cm reference (pos_loss_scale recorded per run).
PhysTwin (upstream 81c7187, isolated copy; scripts/fig1_v01/phystwin): no RGB-D, segmentation, tracking network or
  shape completion; object points = the same RGB-triangulated markers, completed shape = known rest box lattice;
  CMA (20 generations) then Adam (200 iterations); stem stiffness cap raised to Y_max 1e6, dt 2.5e-5.
Ours: posterior over a precomputed FEM grid; observations = markers tracked by Lucas-Kanade in two fitting
  cameras and triangulated from the same RGB frames (no depth for 'ours (RGB)').
FEM control (fem_control.py): see 4.4.
